# 문체와 화면 가이드

모든 강은 이 문서의 기준으로 쓰고 검사한다. 1순위는 **어떻게 하면 가장 잘 이해시키는가**다.
분위기(어둡고 조용한, 오펜하이머·인터스텔라 쪽)는 디자인이 맡고, 문장은 이해를 맡는다.

---

## 1. 하루 한 강

- 20분 안팎, **핵심 개념 하나**, 화면 18~25장
- 흐름: 장면 → 떠올리기 → 새 개념(정의·관찰·단계 설명) → 확인 → 숫자로 → 비유와 그 한계 → (이야기) → 오늘의 문제 → 자기 말로 세 줄 → 다음 강으로
- **오늘의 문제**: 여러 단계를 거쳐야 풀리는 문제 하나. 힌트 세 단계, 마지막에 풀이
- **다음 강으로**: 오늘 배운 것으로 설명되지 않는 사실 하나를 구체적으로 보여주고, 다음 강에서 무엇을 하는지 말한다. 수수께끼로 끝내지 않는다

## 2. 화면 설계

### 2-1. 화면 한 장

휴대폰 세로 화면(390×844) 한 장에 스크롤 없이 들어가는 것이 기준이다.

```
┌────────────────────────────────┐
│ 27강 · 열복사        ▮▮▮▮▯▯▯▯ 4/20 │  진행 표시
├────────────────────────────────┤
│        시각 자료 영역             │  화면 높이의 40~55%, 화면마다 하나
├────────────────────────────────┤
│ 글 2~4문장, 120~250자            │  첫 문장은 앞 화면과의 연결
├────────────────────────────────┤
│  ‹ 이전                 다음 ›   │
└────────────────────────────────┘
```

### 2-2. 화면 종류 (`<Screen kind="…">`)

| kind | 이름 | 시각 자료 | 글 |
|---|---|---|---|
| scene | 장면 | 일상 장면 (`Panels`, `Icon`) | 독자가 겪어 본 상황 |
| recall | 떠올리기 | 원래 강에서 쓴 그림을 그대로 | 그 내용을 실제로 다시 설명. `from={강}` |
| define | 정의 | `<Define term="…" />` | 왜 이 이름이 필요한지 |
| observe | 관찰 | 시뮬레이션 | 조작 지시 → 조작 뒤 해석(`<S n={2}>`) |
| graph | 그래프 읽기 | `Plot`에 `axisSteps`, 요소마다 `step` | 단계마다 한 문장 |
| step | 설명 | 이름표 붙은 도식 | 앞 화면에서 한 걸음만 |
| compare | 비교 | 두 경우를 나란히 | 무엇이 같고 다른지 |
| worked | 숫자로 | 표나 풀이 | 줄마다 왜 그렇게 하는지, 끝에 감각 확인 |
| analogy | 비유 | `<Analogy>` 대응표 | 맞는 곳과 틀리는 곳 |
| check | 확인 | (선택) | `<Check>`, `<Numeric>` |
| story | 이야기 | 연표, 인물 | 사람은 그 문제에 부딪힌 사람으로 |
| problem | 오늘의 문제 | | `<DailyProblem>` |
| three | 자기 말로 세 줄 | | `<ThreeLines>` |
| next | 다음 강으로 | | 구체적인 다음 질문 |

### 2-3. 시각 자료

- 화면당 하나, 메시지 하나, 이름표는 4개까지
- **물리량마다 고정 색**: 시간·주기·진동수(파랑), 거리·진폭·파장(초록), 속력·속도·가속도(보라), 힘·질량·운동량(분홍), 에너지(노랑), 전하(청록), 온도(주홍). 글에서 그 단어에도 같은 색 밑줄이 자동으로 붙는다
- 축 이름은 말로 쓴다: "진동수 (1초에 진동하는 횟수)". 단위 포함
- 빛을 다루는 그래프의 가로축은 사이트 전체에서 **진동수**이고, 오른쪽으로 갈수록 커진다
- 애니메이션은 개념이 움직임일 때만. 움직임을 줄이는 설정이면 자동 재생하지 않는다
- 모든 그림에 대체 텍스트(`alt`)

### 2-4. 글

- 화면당 2~4문장, 120~250자. 한 문장은 대체로 60자 이하
- 첫 문장은 왜 이 화면으로 넘어왔는지 말한다
- 숫자는 말로 먼저("1초에 약 400조 번"), 지수 표기는 2강에서 배운 뒤 함께
- 문장마다 주어와 서술어를 갖춘다. 절을 명사구로 눌러 담지 않는다
- 목표 문체는 잘 가르치는 선생님의 차분한 설명문. "~다" 체

## 3. 용어 계약

**한 번 말했다고 계속 쓸 수 있는 게 아니다.** 끌어다 쓸 수 있는 것은 자세하고 깊게 다룬 내용과 용어뿐이다.

1. 용어마다 **정식 도입 강**(`glossary.yaml`의 `taughtIn`)이 하나 있다. 정식 도입은 정의 카드, 일상 예시 2개, 시각 자료, 확인 문제를 모두 갖춘 것이다
2. 정식 도입 전에는 그 용어를 쓰지 않는다. 필요하면 풀어서 쓴다. 일부러 미리 언급할 때만 `<Later n={강}>…</Later>`로 감싼다
3. 정식 도입 뒤에도 다른 강에서 처음 쓸 때는 괄호 풀이나 떠올리기 화면을 붙인다. 진동수(1초에 진동하는 횟수)처럼
4. **지어낸 말 금지**: 정식 용어가 아닌 줄임말("몫", "떨림")을 만들어 쓰지 않는다
5. **한 물리량에 한 이름**: "진동수"와 "주파수"를 섞지 않는다. 빛은 진동수로 설명하고, 파장이 필요하면 변환 문장을 따로 둔다
6. **비교하는 말에는 대상을 붙인다**: "짧은 쪽" 대신 "진동수가 높은 빛"
7. **그래프 말은 그래프와 함께만**: "꼭대기", "오른쪽"은 그래프가 화면에 있고 축을 말로 읽어 준 뒤에만

`npm run validate`가 1, 2를 강제한다.

## 4. 설명 원칙

- 한 강에 핵심 개념 하나, 한 화면에 새 생각 하나
- 예시는 일상에서, 개념마다 서로 다른 장면 두 개 이상
- 비유는 구조가 같아야 한다. 비유 안에서도 같은 이유로 같은 결과가 나와야 하고, 틀리는 곳을 밝힌다
- 수식은 말 → 그림 → 숫자 → 기호. 기호는 처음 쓸 때 뜻과 단위를 적는다
- 흔한 오해를 먼저 꺼낸다
- 역사는 개념이 선 다음에. 설명 순서와 실제 역사 순서가 다르면 그렇다고 밝힌다
- `mechanism`(이 강이 설명할 원리 한 문장)을 먼저 적고, 본문이 단계별로 설명했는지 확인한다
- 독자가 실제로 해 볼 수 있는 것을 넣는다
- 기록으로 확인된 사실만 쓴다. 출처는 `sources`에

### 화면마다 묻는 점검 질문

- 이 화면에 정식 도입 전인 용어가 있나?
- 이 화면만 읽은 중학생이 모르는 단어가 있나? 무엇과 무엇을 비교하는지 빠진 말이 있나?
- 앞 화면에서 이 화면으로 넘어오는 이유가 글에 쓰여 있나?
- 방향어(쪽, 위, 꼭대기)를 그래프 없이 썼나?
- "그래서 그게 왜?"라는 반응이 나올 곳이 있나?

## 5. 무엇이 AI 말투이고 어떻게 고치는가

계획 단계에서 쓴 예시 글들을 진단한 결과다. `npm run lint:style`이 일부를 자동으로 찾는다.

| # | 문제 | 예 | 왜 AI처럼 읽히나 | 고치는 법 |
|---|---|---|---|---|
| ① | 맥락 없는 고유명사 | "실험물리학자 하인리히 루벤스가 … 막스 플랑크의 집에" | 필자가 아는 걸 독자도 안다고 가정 | 문단당 새 이름 하나, 누구이고 왜 나오는지 문장으로 |
| ② | 수수께끼 결말 | "문제는 그 식이 왜 맞는지였다" | 긴장감 흉내. 질문만 던지고 넘어감 | 무엇을 몰랐고, 무엇을 받아들여야 했고, 무엇이 바뀌었는지 |
| ③ | 날짜로 여는 명사형 문장 | "1900년 10월 7일, 일요일 오후." | 영화 오프닝 템플릿 | 날짜·장소는 타이틀 카드가 맡는다 |
| ④ | 끊어치기·도치 | "…맞지 않는다고." | 번역 소설의 리듬 | 완결된 문장, 인과는 접속어로 |
| ⑤ | 같은 길이 짧은 문장 연속 | | 연결어가 잘려 나감 | 문장 길이는 내용이 정한다 |
| ⑥ | 반전 공식 | "A였다. 문제는 B였다." | 어디에나 끼우는 틀 | 대비가 핵심일 때만, 양쪽을 구체적으로 |
| ⑦ | 지어낸 장면 | "플랑크는 책상에 앉았다" | 그럴듯한 질감을 위해 사실을 꾸밈 | 기록된 것만 |
| ⑧ | 일을 안 하는 디테일 | "아내와 함께", "차를 마시다가" | 분위기용 정보 | 빼서 잃는 게 없으면 뺀다 |
| ⑨ | 이유 없는 중요성 | | 전제하거나 선언만 함 | 무엇이 달라지는지 결과로 |
| ⑩ | 번역투 | "실험물리학자 하인리히 루벤스가", "그는" | 영어 구문 직역 | 역할은 문장 안에, 사람은 이름으로 |
| ⑪ | 독자 위치를 무시한 밀도 | "긴 파장", "기존 공식", "측정값" | 필자 기준으로 씀 | `assumes`·`introduces` |
| ⑫ | 빠른 전개 | 다섯 문단에 개념 열두 개 | 빠짐없이 담으려는 요약 습관 | 한 강 한 개념, 한 화면 한 생각 |
| ⑬ | 설명 대신 경위 | 누가 무엇을 했는지만, 왜 맞는지는 없음 | 역사는 쉽고 원리는 어려워서 건너뜀 | `mechanism`을 먼저 적고 확인 |
| ⑭ | 구조가 다른 비유 | "1원 단위로 못 내고 동전으로만" | 모양만 닮고 원리는 안 닮음 | 비유 안에서도 같은 이유로 같은 결과 |
| ⑮ | 지어낸 말을 용어처럼 | "몫", "떨림의 종류" | 필자는 뜻을 아니까 명확하다고 착각 | 진짜 용어를 정식 도입 강에서 가르친다 |
| ⑯ | 눌러 담은 명사구 | "가장 세게 내는 파장" | 절 하나를 명사구로 압축 | 주어와 서술어가 있는 문장으로 |
| ⑰ | 그래프 없는 방향어 | "짧은 쪽으로 옮겨 간다", "언덕" | 필자 머릿속 그래프를 독자도 본다고 가정 | 용어 계약 7번 |
| ⑱ | 한 번 언급 = 배운 것 | "24강의 규칙에 따르면" | 강 번호를 대면 설명한 것으로 착각 | 떠올리기 화면에서 실제로 다시 설명 |
| ⑲ | 같은 것을 두 이름으로 | "파장이 짧은"과 "진동수가 높은"이 섞임 | 바꿔 쓰면 덜 반복적이라는 습관 | 한 물리량에 한 이름 |

그 밖에 금지: 질문으로 시작하는 도입, 질문 연발, 개념의 의인화("자연은 허락하지 않았다"), 장식 은유("실재의 커튼"), 무엇이든 셋으로 묶기, 문단 끝 한 줄 여운, "여러분", "~에 대해 알아보겠습니다", "핵심은", "정리하자면", "흥미롭게도", "놀랍게도", 쌍점·줄표로 극적 효과 내기, 느낌표.

### 고친 예

| 전 | 문제 | 후 |
|---|---|---|
| 가장 세게 내는 파장이 짧은 쪽으로 옮겨 간다 | ⑯⑰⑲ | 온도가 오르면, 물체가 내는 여러 빛 가운데 가장 세게 나오는 빛이 1초에 더 많이 진동하는 빛으로 바뀐다 |
| 떨림 하나하나가 같은 몫을 받는다 | ⑮⑱ | (에너지 등분배와 진동 모드를 정식으로 가르친 뒤) 온도가 정해지면 상자 안 빛의 진동 모드 하나하나가 평균적으로 같은 양의 에너지를 갖는다 |
