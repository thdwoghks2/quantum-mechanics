# 말투 문제 정리

강의를 쓰면서 말투에서 걸렸던 문제와, 그걸 어떻게 막았는지 모아 둔다.
규칙 자체는 `docs/STYLE.md`, 자동 검사는 `scripts/lint-style.mjs`에 있다.

## 1. 처음 원고의 문제

| 문제 | 어땠나 | 바꾼 것 |
|---|---|---|
| 글말 `~다` | 교과서처럼 딱딱하고 거리가 멀었다 | 해요체로 바꿈 |
| "필자" | 책에서나 쓰는 말이라 어색했다 | "저(제가)"로 바꿈 |
| 어려운 말 | 잘 안 쓰는 한자어, 고유명사, 줄인 표현을 썼다 | 흔히 쓰는 쉬운 말을 씀 (예: "이 말이 아닌 것" 대신 "예외", "헷갈림 주의") |
| 비튼 문장 | 문장 구조를 꼬거나 이상한 말로 길게 늘어놓았다 | 말하듯 자연스러운 순서로 씀 |
| 혼자 설명하는 말투 | 함께 배우는 사람이 없었다 | 한 사람이 같이 배우듯, 헷갈리는 곳에서는 다시 보거나 천천히 풀어 줌 |
| 세 줄 요약 | 마지막에 쓰기 부담스러웠다 | 한 문장(OneLine)으로 줄임 |
| 마지막 점검 | 길고 계산 위주였다 | 짧은 생각 문제와, 용어·흐름 복습(Recap)으로 바꿈 |

## 2. 고친 뒤에도 남은 문제 (1강 시범본)

해요체로 바꾼 1강을 폰으로 보니, 정해 둔 규칙을 어기고 있었다.

- 한 화면에 문장이 5~7개 → 꽉 차고 답답하며, 속도가 빠르게 느껴졌다.
- 76~84자짜리 긴 문장이 있었다.
- 같은 어미(`~요`)가 일곱 번 연달아 나왔다 → 말하는 느낌이 아니라 읽는 느낌이 들었다.
- 말 거는 문장을 너무 많이 넣으면 수다처럼 된다 → 가르치는 말투를 기본으로 두고, 혼잣말이나 대화 같은 줄은 한 강에 2~3번만 넣는다.

**원인:** 규칙이 문서에만 있고 검사가 없었다. 그래서 쓰는 사람이 놓쳐도 아무도 몰랐다.

## 3. 막은 방법

`npm run lint:style`이 아래를 잡는다. 하나라도 걸리면 배포 전 검사에서 실패한다.

| 검사 | 기준 |
|---|---|
| 금지어 | "필자" |
| 글말 섞임 | 해요체 강에 `~다`로 끝나는 문장 |
| 한 번에 보이는 양 | 한 번에 보이는 문장 3개 이하, 한 화면 5개 이하 |
| 문장 길이 | 75자 이하 (핵심 문장 Key는 예외: 천천히 길게 써도 됨) |
| 어미 반복 | 같은 어미 4번 연속 금지 |
| 강조 겹침 | Key와 Note를 한 화면에 같이 두지 않음, Note는 4문장 이하 |

그 밖에 사람이 지키는 규칙:

- 예시는 대중적인 것만 쓴다: 유명한 영화 장면, 누구나 아는 사건과 흐름. 몇몇만 아는 이야기는 쓰지 않는다.
- 명언과 대사는 출처가 확실한 것만 쓴다(지어낸 아인슈타인 명언 금지).
- 강마다 머리에 명언이나 영화 대사 한 줄(epigraph)을 둔다.

## 4. 여러 세션이 나눠 쓸 때

세션 다섯 개가 강을 나눠 쓰면서, 세션마다 말투가 달라질 위험이 있었다. 그래서 이렇게 맞췄다.

- 모든 세션이 같은 규칙(`docs/STYLE.md`)과 같은 기준 강(1강)을 보고 썼다.
- 위 자동 검사를 통과해야만 합칠 수 있게 했다.
- 마지막에 세션이 바뀌는 경계 11곳에서, 앞 강의 "다음 강으로"와 뒤 강의 첫 화면이 이어지는지 확인했다.
