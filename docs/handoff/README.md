# 세션 다섯 개로 137강까지 끝내기

남은 일 전부를 다섯 세션이 동시에 나눠 끝낸다. 세션마다 고칠 파일과 구역이 정해져 있어서 서로 부딪히지 않는다.
각 세션은 이 문서와 자기 번호의 문서(`session-1.md` ~ `session-5.md`)를 읽고 시작한다.

| 세션 | 맡은 일 | 부 |
|---|---|---|
| 1 | 2~20강 다시 쓰기 + 21~36강 새로 쓰기 | 0~2부 |
| 2 | 37~63강 새로 쓰기 | 3~7부 |
| 3 | 64~83강, 106~110강 새로 쓰기 + 기존 인물·사건 문장 정리 | 8~10부, 13부 |
| 4 | 84~105강, 111~120강 새로 쓰기 | 11부, 12부, 14부 |
| 5 | 디자인, 보상, 화면 문구 + 121~137강 새로 쓰기 | 15~16부 |

## 1. 모든 세션이 지킬 것

1. **서브에이전트(Agent 도구)와 Workflow 도구는 쓰지 않는다.** 모든 작업을 그 세션에서 직접 한다.
2. **출발점과 브랜치**
   ```sh
   git fetch origin claude/great-darwin-0g3mr0
   git checkout -B <이 세션에 지정된 작업 브랜치> origin/claude/great-darwin-0g3mr0
   npm ci
   ```
   푸시는 이 세션에 지정된 작업 브랜치로만 한다. `claude/great-darwin-0g3mr0`, `main`, 기본 브랜치에는 푸시하지 않고, PR도 만들지 않는다. 합치기는 원래 세션이 한다.
3. **자주 저장**: 강 하나를 끝낼 때마다 커밋하고 바로 푸시한다. 세션이 중간에 끊겨도 일이 남게 한다.
4. **자기 파일과 자기 구역만 고친다**(아래 2장 표). 남의 구역을 고쳐야 하면 고치지 말고 끝 보고에 적는다.
5. **기준 문서**: `docs/STYLE.md` 전체, 특히 다음을 먼저 읽는다.
   - 2장 목소리, 2-3 속도와 밀도, 4장 용어 계약
   - `docs/ADDING_CONTENT.md`(강 틀, 컴포넌트, 시뮬레이션 만드는 법)
   - `src/content/curriculum.yaml`(137강 전체 목록과 강마다 다룰 것)
6. **본보기**: 1강 `src/content/lessons/00-basics/001-what-physics-does.mdx`. 새 말투와 속도 규칙을 모두 지킨 강이다. 1강은 고치지 않는다.
7. **검사**: 강 하나마다 `npm run validate`와 `npm run lint:style`을 돌린다. 내 강에서 경고가 0건이어야 한다. 끝나기 전에는 `npm test`와 `npm run build`도 통과해야 한다.
8. **커밋**: 영어 명령형 제목과 필요한 본문. 모델 이름은 적지 않는다.
9. **끝 보고**(세션 마지막 메시지)에 적을 것:
   - 작업 브랜치 이름과 커밋 목록, 끝낸 강 번호와 못 끝낸 강 번호
   - 사실 확인이 더 필요한 곳
   - 남의 구역에서 고쳐야 할 것(예: 앞 강이 쓰는 말이라 `previewIn`을 더해야 하는 용어, 이미 있는 인물에 더할 `lessons`)

## 2. 누가 무엇을 고치나

| 파일 | 고치는 세션 |
|---|---|
| `src/content/lessons/**` | 자기 강 번호의 파일만. 새 부의 폴더 이름은 아래 4장 |
| `src/content/glossary.yaml` | 자기 강 번호의 구역(`# ── N강`)만. 세션 1은 2~20강 구역도 |
| `src/content/curriculum.yaml` | 자기 부의 줄만(부의 `summary`, 강의 `title`, `note`) |
| `src/content/people.yaml`, `events.yaml` | 맨 아래 "세션 N" 자리 아래에 새 항목만 더한다. 위의 기존 항목은 세션 3만 고친다 |
| `src/components/sims/Sim*.astro` | 새 파일만 만든다. 이름 앞에 부 번호를 붙여 겹치지 않게 한다(예: `SimP08Box.astro`). `index.ts`는 고치지 않는다(저절로 등록된다) |
| `src/components/figures/icons/session-N.ts` | 자기 번호 파일에만 새 아이콘을 더한다(`icons/README.md`) |
| 그 밖의 `src/**`, `scripts/**`, `docs/**`, `tests/**` | 세션 5만. 다른 세션은 고치지 않는다 |
| `docs/CURRICULUM.md` | 아무도 만들지 않는다(합칠 때 만든다) |

## 3. 용어 지도

- 21~137강의 용어는 `glossary.yaml`에 **이미 이름과 강 번호가 정해져 있다**(`planned: true`, 정의는 "(준비 중)").
  - 그래서 다른 세션이 쓰는 앞 강의 용어도 `assumes`에 id로 바로 쓸 수 있다. 예: 64강의 `assumes`에 58강의 `wavefunction`.
  - 아직 내용이 비어 있어도 검사는 통과한다.
- 자기 강을 쓸 때 할 일:
  - 그 강의 용어 항목에 `definition`, `examples`(해요체, 일상 장면 두 개 이상), `notThis`를 채우고 `planned: true` 줄을 지운다. 공개한 강이 planned 용어를 가르치면 검사가 실패한다.
  - `q`(물리량 색)와 `highlight`는 필요하면 정한다.
- **id는 지우거나 바꾸지 않는다.** 다른 세션이 그 id를 쓰고 있다. 용어 이름(한국어)을 바꿔야 하면 바꾸고 끝 보고에 적는다.
- 내 강에 용어가 더 필요하면 내 구역에 새 항목을 더한다.
- 내 강 글에 뒤 강의 용어를 써야 하면 `<Later n={그 강}>…</Later>`로 감싼다. 남의 구역의 `previewIn`은 고치지 않는다.
- "온도", "평균"처럼 아주 흔한 일상어는 용어로 두지 않았다.

## 4. 새 강 쓰기

- 파일: `src/content/lessons/<부 폴더>/<세 자리 강 번호>-<영어 slug>.mdx`
- frontmatter의 `part`는 `curriculum.yaml`의 부 번호와 같아야 한다.
- 부 폴더 이름:

| 부 | 폴더 | 부 | 폴더 |
|---|---|---|---|
| 2 | `02-heat-light` | 10 | `10-state-vectors` |
| 3 | `03-atoms` | 11 | `11-interpretations` |
| 4 | `04-matter-waves` | 12 | `12-relativity` |
| 5 | `05-complex-numbers` | 13 | `13-nuclei-stars` |
| 6 | `06-amplitudes` | 14 | `14-bomb` |
| 7 | `07-uncertainty` | 15 | `15-fields-cosmos` |
| 8 | `08-schrodinger` | 16 | `16-applications` |
| 9 | `09-periodic-table` | | |

- 강마다 갖출 것(`docs/ADDING_CONTENT.md`의 틀):
  - `status: published`, 화면 22~30장, 모든 화면에 `title`
  - 확인 문제 3개 이상, `testout` 3개
  - 강 끝: 되짚기, 마지막 점검, 한 문장으로, 다음 강으로
  - `sources`에 실제 문헌
- **시각 자료**:
  - 개념이 움직임이나 과정이면 시뮬레이션을 만든다. 기존 시뮬레이션을 다시 써도 된다.
  - 역사와 생각을 다루는 강은 `Panels`, `BigNumber`, `DataTable`, `Flow`, `Plot`으로 충분하다.
  - 움직임을 줄이는 설정이면 시뮬레이션이 자동 재생하지 않게 한다.
- **한 권의 책처럼**:
  - 첫 화면은 앞 강의 "다음 강으로"가 예고한 것을 받는다. 앞 강이 다른 세션 몫이라 아직 없으면, `curriculum.yaml`의 앞 강 `note`를 보고 이어지게 쓴다.
  - 내 범위 마지막 강의 "다음 강으로"는 다음 강의 `note`를 예고한다.
  - 앞에서 배운 걸 다시 쓸 때는 떠올리기 화면(`kind="recall" from={강}`)으로 실제로 다시 설명한다.
- **사실**:
  - 연도, 이름, 숫자, 인용은 기록으로 확인된 것만 쓴다. 지어낸 장면이나 대사는 쓰지 않는다.
  - 인물의 말은 출처가 분명할 때만 짧게 인용한다.
  - 핵무기와 전쟁을 다루는 강은 피해와 책임을 정확하고 차분하게 쓴다.

## 5. 1강 검토에서 실제로 걸린 실수 (강을 쓰는 모든 세션)

1. 한 번에 보이는 글이 4문장 넘음, 화면 하나에 5~7문장. → 3문장까지, 넘으면 `<S n={2}>`로 나누거나 화면을 쪼갠다
2. 60자 넘는 문장이 많음. → 60자 안팎, 75자를 넘기지 않는다(`<Key>`만 예외)
3. "~어요."로 끝나는 문장이 일곱 번 이어짐. → "~거든요"(이유), "~잖아요"(같이 아는 것), "~죠"(확인), "~이에요"를 섞는다
4. `<Key>`가 짧은 선언 + 예시 두 문장. → 조건과 이유를 다 담은 한 문장
5. 가장 중요한 문장에 어려운 말("~위에서 성립", "곧", "꿰다"). → 쉬운 말
6. 학문을 사람처럼("물리학이 예측했다"), 직함을 이름 앞에 쌓기("영국의 물리학자 아이작 뉴턴이"). → "사람들이 그 법칙으로 예측했어요", "아이작 뉴턴은 ~"
7. 질문을 던지고 답을 다음 화면으로 미룸. → "왜 그럴까요?" 바로 다음 문장에서 답한다
8. `<Note>`를 덧붙이는 사실에 씀. → 아이들이 실제로 헷갈리는 곳에서 멈춰, 다른 예로 다시 짚을 때만. 한 강에 한두 개
9. 정의 화면 글이 정의 카드를 되풀이. → 앞 화면과 이어서 왜 이 이름이 필요한지
10. 확인 문제에 필요한 조건이 빠짐(복습 목록에 혼자 실리면 못 풂). → 문제 글 안에 조건을 다 담는다
11. 마지막 점검이 강에서 안 가르친 지식(요리 상식)을 물음. → 오늘의 원리로 생각하는 짧은 문제 하나, 힌트 한두 개
12. 해를 맨눈으로 보라는 말처럼 읽힘. → 위험한 행동에는 안전 문구
13. 대화하듯, 혼잣말처럼 쓰는 건 한 강에 두세 번까지만. 바탕은 가르치는 목소리
