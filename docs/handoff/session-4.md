# 세션 4: 디자인, 보상, 화면 문구

먼저 `docs/handoff/README.md`를 읽는다. 거기 적힌 규칙(서브에이전트·Workflow 금지, 브랜치, 검사, 보고)을 그대로 따른다.

## 사용자가 한 말

> 이젠 문제가 디자인이야. 폰에서 보니 너무 답답하고 꽉 차 있고 재미가 없어. 너무 글로만 있고 속도가 빠르다고 체감할 수 있을 수도 있어.
> 투박하고 살짝 어두운 분위기는 좋아.
> 뭔가 게임 같진 않고 오펜하이머와 인터스텔라, 깊은 과학과 지적 수준이 올라가는 보상 체계를 간단히만 설계하고 싶어.

글의 양은 세션 1, 2, 3, 5가 줄이고 있다(STYLE 2-3: 한 번에 3문장까지, `<S>` 단계로 나눠 보여 주기). 이 세션은 **같은 글이 휴대폰에서 숨 쉬고, 한 장씩 천천히 음미되게** 만든다.

## 고치는 파일

- `src/styles/*`, `src/layouts/*`, `src/pages/**`(새 페이지 포함), `src/lib/**`, `tests/**`
- `src/components/**`. 단 `src/components/sims/index.ts`와 `src/components/figures/Icon.astro`는 고치지 않는다(세션 5가 새 시뮬레이션과 아이콘을 더한다).
- `docs/STYLE.md`의 3장(화면 설계)과 `docs/ADDING_CONTENT.md`의 컴포넌트 표(새 컴포넌트를 만들었을 때), `docs/REWARDS.md`
- `scripts/*`는 새 컴포넌트 때문에 꼭 필요할 때만 고치고, 끝 보고에 적는다.

강 파일(`src/content/lessons/**`), `src/content/*.yaml`은 고치지 않는다. 다른 세션이 고치고 있다.

## 지금 구조에서 꼭 알아야 할 것

- 사이트는 Astro `ClientRouter`로 페이지를 바꿔 끼운다. 배경 음악이 끊기지 않게 하려는 것이다. 그래서 페이지 스크립트는 `document.addEventListener('astro:page-load', init)`에서 실행하고, `init` 첫 줄에서 `[data-page="…"]`로 자기 페이지인지 확인한다(`src/pages/course.astro` 참고). 새 페이지도 이 방식을 따른다.
- 강 화면은 `qm-lesson` 커스텀 요소(`src/lib/client/lesson.ts`)다. 문서에 거는 이벤트는 `disconnectedCallback`에서 뗀다.
- 배경 음악은 `src/lib/client/music.ts`와 `src/components/music/*`. 망가뜨리지 않는다.
- 움직임을 줄이는 설정(`prefers-reduced-motion`)에서는 움직임을 끈다.
- 시험 브라우저: Playwright와 Chromium이 이미 깔려 있다(`require('playwright')`). `npm run build && npx astro preview`로 띄워 390×844 화면을 찍어 보며 작업한다.

## 할 일

### 1. 디자인 (휴대폰 먼저, 390×844)

- **숨 쉴 공간**: 강 화면의 줄 간격, 문단 사이, 그림과 글 사이를 넓힌다. 본문은 휴대폰에서 17~18px. 위 막대(lbar)와 아래 넘기기 막대(lnav)를 더 얇게, 진행 막대를 더 가늘게.
- **한 장씩 천천히**: `<S>` 단계가 남아 있으면 "계속"이 다음 화면과 구별되게 보이게 한다(예: 버튼 글자와 모양을 바꾸고, 다음 단계 자리에 희미한 표시). 단계가 열릴 때 부드럽게 나타나게.
- **화면마다 다른 얼굴**: 지금은 모든 화면이 "그림 + 글 덩어리"로 같아 보인다. 화면 종류(`data-kind`)마다 배치를 달리한다.
  - 정의: 용어를 크게
  - 핵심 문장(`<Key>`): 화면 가운데에 크게, 여백을 넉넉히
  - 이야기: 연도를 크게, 더 어둡게
  - 확인 문제: 카드
  - 되짚기: 목록이 차례로
  - 글만 있는 화면: 큰 글씨로 가운데에
- **질감**: 지금의 필름 입자는 유지하고, 칠판(오펜하이머)과 별과 먼지(인터스텔라)의 결을 절제해서 더한다. 강조색(주황)은 아껴 쓴다.
- **다른 페이지들**(홈, 코스, 용어집, 연대기, 인물, 복습, 기록, 진단): 덜 빽빽하게, 위계가 한눈에 보이게.
- **끝내는 기준**:
  - 390×844에서 가로 스크롤이 없다.
  - 1강의 모든 화면이 단계를 다 열어도 글 영역 안에서 스크롤하지 않는다. 지금은 "모형이라는 이름" 화면이 37px 넘친다.
  - 바꾸기 전과 후의 주요 화면 캡처를 끝 보고에 경로로 적는다.

### 2. 보상 (`docs/REWARDS.md`대로)

- **별 지도**: 끝낸 강마다 별이 켜지고, 부마다 별자리. 코스 페이지 위에 크게, 홈에 작게.
- **지금 서 있는 해**: 마지막으로 끝낸 강과 이어진 사건의 연도로 한 줄. 부를 마치면 강 끝에 장 넘김 화면 한 번.
- **내 칠판**: 끝낸 강마다 칠판 한 칸에 내가 쓴 한 문장(`notes.one`)과 그 강의 `<Key>` 문장. 새 페이지 "칠판", 사이트 메뉴에 추가. `<Key>` 문장은 빌드할 때 강 파일에서 뽑는다.
- 점수, 배지, 연속 기록, 효과음은 넣지 않는다. 새로 저장하는 값은 없다.
- `tests/`에 별 상태, 서 있는 해 계산 같은 순수 함수의 테스트를 더한다.

### 3. 화면 문구 (새 말투)

STYLE 2장 말투로 바꾼다. 이름표와 버튼은 짧은 명사형도 된다. 홈(`index.astro`)과 강 화면의 문구는 이미 바꿨으니 남은 "~다" 문장만 확인한다.

- `src/pages/`의 course, glossary, people, timeline, review, settings, placement
- `src/lib/placement.ts`의 진단 문제(`q`, 선택지 `t`, `why`). 정답과 내용은 그대로 두고, 문제 글 안에 조건을 다 담는다.
- `src/components/sims/*.astro`와 `src/lib/client/sim.ts`의 라벨, 버튼, 설명, 출력 문장
- `src/components/figures/*`, `src/components/kinds/*`의 남은 문구
- `src/lib/progress.ts`의 내보내기 글, `src/layouts/Base.astro`의 description
